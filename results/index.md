> **Ignore the container column for scenarios 003 and 005.** Both talk to something running on the host, so the containerised runtime has to reach it as `host.docker.internal` — out through the VM's NAT, onto the host, back in through a published port. The comparable arrangement is container-to-container on a shared Docker network, which this harness does not do yet. See [METHODOLOGY.md](../METHODOLOGY.md).
